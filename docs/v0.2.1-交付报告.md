本轮以 v0.2.0 为基线做增量修复，没有重写进程边界、MCP 工具契约或研究数据模型。核心结果：

- Sidebar 折叠/展开稳定，折叠态控制完整落在 58px 轨道内；连续切换、窗口缩放、刷新恢复均有回归验证。
- Dock 关闭不再卸载面板，未保存设置、报告滚动和论文标签可恢复。
- 后端 409/401 等错误正文透传到 UI；SSE 致命错误、事件快照覆盖、恢复轮询过早停止等问题修复。

- 前端 light/dark token、动效 token、排版/对比度/空态/错误态统一；核心回归和打包解包版 E2E 均通过。
- 清理了无引用的旧 Qt/PySide6 源码残留、陈旧嵌套锁文件和可再生缓存；用户数据、密钥、历史、PDF/报告未删除。

## 3. Sidebar 折叠问题：根因与修复

**直接原因**：58px 侧栏的内容盒约 57px，折叠态 `.sidebar-brand` 水平内边距 8px 后可用的宽度约 41px；品牌标记 34px + gap 11px + 折叠按钮 31px 共 76px，按钮被推到轨道外，又被 `.sidebar { overflow: hidden }` 裁切。展开按钮只剩约 21.5px 可见，系统缩放或字体放大时会进一步不可点。

**状态原因**：`layout.sidebarCollapsed` 与视口 `compact` 共同决定 rail，但 sidebar 样式只在 `<900px` 媒体查询中定义；在 900–1179px 折叠时进入“状态已折叠、rail 样式未生效”的空档。小窗口折叠后按钮又被媒体查询隐藏，折叠状态持久化后回到大窗口仍可能无法展开。

**修复**：

1. `WorkspaceShell` 计算单一 `rail = compact || layout.sidebarCollapsed`，inline `--sidebar-width` 在 rail 时为 58px；移除 `!important` 视口宽度覆盖。
2. 展开态折叠按钮留在 header；折叠态改为 footer 内 36px 展开按钮，完整落在 58px 轨道内；compact 视口不渲染切换按钮。
3. 将 rail 的文本隐藏、会话行、设置按钮样式统一到 `.sidebar-compact` 类作用域，覆盖 900–1179px。
4. rail 时禁用并隐藏侧栏拖拽手柄；修正 stacked 布局 Dock 宽度/高度计算；拖拽增加 pointer capture、`pointercancel`、`blur`、`Escape` 清理。
5. 回归：快速连点、折叠后刷新、1024px 折叠、Dock 同时打开、主区域宽度变化均通过。

## 4. 业务流程验证

### 4.1 小规模真实链路

- 查询：`long-term memory agent token efficiency`；top_k=1。
- arXiv/OpenAlex 各返回 6 条真实记录；Selector 选中 1 篇。
- 真实 PDF 下载/转换得到 1 篇 `partial_fulltext`；单篇总结 `partial_fulltext`；报告 `partial`，正文 7,942 字符。
- 总墙钟约 219 秒；物理模型请求 8 次、41,501 token。
- 保留真实错误：无 OA、部分页提取、下载超时、部分总结、部分报告。
- 证据：`data/validation/v021/stress/20261024T094130Z/`。

### 4.2 40/40/30/8 大规模链路

- 配置：arXiv `source_limit=40`、OpenAlex `source_limit=40`、`merged_candidate_limit=30`、`top_k=8`、`max_fulltext_attempts=12`、`report_budget=128000`、`download_timeout=90`。
- 结果：原始 80 条（40+40）、唯一 59 条、下游 30 条、Top-8 选中；14 次全文尝试后 8 篇可读全文；8 份总结（5 份 partial、3 份 failed）。
- 阶段耗时：search 9.2s、selection 6.9s、fulltexts 128.7s、summarize 298.3s、total 443.4s。
- 物理模型请求 56 次、347,389 token。
- 首次报告输入 130,613 字节超过旧预算；增加独立报告预算并把每篇证据限制为前 3 条后，8 摘要报告重试成功：摘要 2,417 字符、正文 13,875 字符、5 条引用，仅保留 `partial_report`。中间一次模型输出被引用校验拒绝，按 `invalid_model_output` 保留。
- 证据：`data/validation/v021/stress/20261024T095920Z/`、`data/validation/v021/report-regeneration-8b/`。

### 4.3 诚实边界

以上证明真实来源、真实 PDF、真实模型调用、Selector、总结、报告和失败保留的可运行性；不证明论文相关性、模型判断正确、完整科研成功或性能提升。Demo/合成运行单独标记，不能替代 live 质量结论。

## 5. 性能与规模

- 新增 `scripts/stress_run.py`，支持 demo/live、40/40/30/8、独立输出目录、预算预检、整体超时和 stress-summary.json。
- 新增 `merged_candidate_limit`、`selector_input_token_budget`、`report_input_token_budget`、`max_fulltext_attempts`；默认保持小规模开发行为。
- 报告提示只发送每篇前 3 条证据，完整证据仍保存在单篇 summary artifact。
- 未执行 v0.2.0↔v0.2.1 的同输入、≥5 轮配对基准，因此不宣称加速比；真实计时已按阶段记录。
- 第一次大规模运行（60 秒下载预算）出现多条 `download_timeout`；最终 90 秒配置消除了下载超时，主要真实失败变为 4 条部分页提取、2 条无 OA 和 8 条模型输出/部分总结问题。默认仍为 60 秒，stress 可用 `--download-timeout` 调整。
