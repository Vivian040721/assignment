## 材料关联根因与修复

### 根因

`web.py` 旧逻辑先按 `run.papers` 建 artifact 映射，再用 `run.selected_papers` 覆盖同一 `paper_id`。本次 Job 中：

- SYNC 在 `run.papers` 中是已下载、已转换、有 `pdf_path` 的记录；
- SYNC 在原始 `selected_papers` 中仍是 `status=selected`、无文件和 artifact 的记录。

覆盖后，已准备好的 SYNC 文件信息被原始选择记录抹掉，最终 artifact 列表没有 SYNC PDF。同时，简报调用 `build_research_brief(papers=run.selected_papers or run.papers)`，只看到原始三篇选择，看不到实际进入分析的 Lost in the Middle 和 Stronger Baselines。

### 修复

- 新增按稳定 `paper_id` 的材料合并：`run.papers` 的全文、路径、阅读状态优先；原始 `selected_papers` 仅补充缺失的选择/排序字段，不覆盖已准备材料。
- 新任务和旧任务的运行结果都使用合并后的实际材料生成 artifact 与简报。
- 旧 Job 在服务启动载入时重建派生视图（artifact ID 与简报）；不改写原始 run JSON，不改变执行状态、交付状态或历史成功边界。
- `pipeline.py` 的直接运行也改为从实际 `papers` 构建简报，避免绕过桌面服务时再次丢论文。
- 推荐下一步优先取自报告已有的 `research_directions`，不再固定为“补全文再生成报告”。本次显示：
  “在共享上下文框架内加入位置因子：对同一检索任务分别把目标信息置于首、中、尾，比较检索命中与后续推理正确率的分离程度，需实证检验。”

隔离副本验证结果：

- 简报关键论文：3 篇，分别为 SYNC、Lost in the Middle、Stronger Baselines。
- 三条关键发现分别来自上述三篇论文。
- SYNC 获得真实 PDF artifact：`469aa1e3f4dde9d1435f`。
- 交付状态仍为 `preliminary_notes`。

## PDF 空白根因与修复

### 根因

旧实现把 PDF 字节包装为 Blob URL，再交给 `<iframe>`，依赖 Chromium 内置 PDF 查看器。Electron 当前运行时不提供该查看器，因此工具栏、页码和 Blob URL 都存在，但 iframe 内没有任何 PDF 页面。空白不是文件读取失败，也不是 artifact 鉴权失败。

### 修复

- 移除 iframe/Blob URL 阅读路径，改用本地打包的 PDF.js，将 PDF 页面绘制到 `<canvas>`。
- 保留受控 `readPdfArtifact(jobId, artifactId)` 获取字节；renderer 仍不接触本地 PDF 路径。
- 工作线程资源随构建产物打包，CSP 显式允许同源 worker；不再需要 Blob frame/object 权限。
- 支持真实页数、上一页/下一页、页码跳转、50%–200% 缩放、专注阅读、实际全文检索和匹配位置翻页。
- 搜索逐页提取 PDF 文本并返回真实匹配数和上下文；未匹配时明确显示“没有找到匹配文本”。
- 读取、格式或渲染失败时显示可操作说明，不再留下长期空白。
- 研究笔记中的证据页码继续可跳转到对应 PDF 物理页。
