## 2. 修改文件与关键行为

### 2.1 证据定位契约（角色 7，角色 1 协调）

文件：`src/paper_agent/agents/research_agent.py`、`src/paper_agent/demo_fixtures.py`、`tests/unit/test_research_agent.py`（测试 fixture 静态同步）。

- 新 chunk evidence 只接受四个必需字段：`source_segment_id`、`quote`、`claim`、`evidence_type`；`_ChunkEvidence` 使用 `extra="forbid"`。
- chunk 阶段禁止 `evidence_id`；若模型返回该字段，记录 `chunk_evidence_id_forbidden` 并失败。`evidence_id` 只在全部 chunk 笔记验证后由程序按稳定顺序分配为 `e1...`。
- 程序在当前 chunk 的合法 segment 集合中解析 `source_segment_id`，仅做 NFKC/空白归一化后验证 quote 是否在该段连续命中；未知 ID、跨段/拼接 quote、非法枚举、未知字段继续失败。
- 程序从可信来源绑定 `paper_id/page_number/section`：
  - `page_number` 只来自整份 `page_map` 通过校验的页面段；页码映射缺失、重复、重叠、越界、文本不一致或 `page_count` 不一致时，整份映射隔离，页码保持 `null` 并写入审计。
  - `section` 依据 quote 在该段内的真实起始位置取最近标题，而不是整页开头标题；同一 quote 多次出现且落在不同章节时保持 `null` 并记录 `ambiguous_section_quotes`。
  - 跨页 gap 或无法映射的段保持 `null`，不猜测。
- 旧输出兼容分支：若 evidence 带 `paper_id/page_number/section`，先弹出并按来源严格比对；`paper_id` 冲突、页码与来源不一致、来源无页码却声称页码、章节冲突或来源无章节却声称章节均失败，不会静默覆盖成成功。旧 `paper_id/page/section` 不进入新 schema。
- 审计：每个总结目录写 `<summary>.audit.json`；完整 chunk 笔记和全部验证证据写 `<summary>.chunks.json`；契约版本、总/有效/失败 chunk、失败子原因计数、页码/章节绑定/null/歧义计数、修复使用情况写入 sidecar；紧凑版本写入 `paper.metadata["research_audit"]`。`web.py` 将两个 sidecar 注册为 `chunks`/`audit` artifact。

### 2.2 merge 有界输入（角色 7）

文件：`src/paper_agent/agents/research_agent.py`。

- 完整 chunk notes（含 `evidence_ids`）和全部 verified evidence（含 `source_segment_id`、页码/章节）在 merge 前另存为 `<summary>.chunks.json`，不被压缩内容覆盖。
- merge 输入改为 `facts` + 共享 `verified_evidence` 目录：
  - 精确重复事实按 `(theme, normalized text)` 去重，并保留全部 `chunk_ids`/`evidence_ids`；不同数字、条件、结论或局限不合并。
  - evidence catalog 一次，去掉重复的 `paper_id`、`claim`、`source_segment_id` 等元数据；事实用稳定 `eN` ID 关联；每个事实同时保留来源 chunk ID。
  - theme 包括 question/mechanism/method/experiment/finding/limitation/author_claim/system_inference/research_idea。
- 预算边界：继续使用 `_size = UTF-8(system + JSON) + 64` 与 `settings.llm_input_token_budget`（默认 24000），不增加调用、token、输入/输出或修复预算；修复检查继续计入 `REPAIR_INSTRUCTION`。
- 分级策略（均在内存中确定性完成，不调用模型）：
  1. 全 facts/evidence 完整结构化 payload；
  2. 若超预算，仅确定性缩短引文（240/180/140/100/80/60 字符）；
  3. 仍超预算，做 chunk+theme 覆盖选择：优先方法/机制/实验/发现/局限，按 chunk 轮转与与问题词面相关性排序，不按开头截断；
  4. 覆盖选择可再用引文上限；最低必要 theme 放不下则不做 merge。
- `merge_input_audit` 记录：原始/提交保守单位、系统提示长度、各 chunk/theme 保留与遗漏、全部保留/遗漏 fact ID 与 evidence ID、去重映射、coverage gaps、选择方式、merge 是否调用/完成、失败原因。完整审计在 sidecar，pipeline `metrics.merge_input_audit` 保留计数、范围、缺口和状态。
- 有损压缩若 merge 成功，程序新增 `partial_synthesis` 错误并明确提示“受限综合”；不会因 merge 成功升级为完整。最低内容放不下时保留结构化笔记并报 `llm_budget`/`input_budget`，不拼接长文冒充 `deep_analysis`。
- `overview`/`deep_analysis` 仍由同一次论文级 merge 生成；每篇 chunk/merge 共享原有最多一次反馈修复。

### 2.3 点名召回与身份区分（角色 4/5，必要时 2/3）

文件：`src/paper_agent/services/retrieval.py`、`src/paper_agent/services/pipeline.py`、`src/paper_agent/agents/selector_agent.py`、`src/paper_agent/sources/openalex_source.py`。

- 短名称查询仍在原最多 3 条 query、每来源请求上限内执行；当规划 query 只等于某个用户点名目标时，转换为源原生标题查询：
  - arXiv：`ti:"<安全规范化目标>"`，复用既有显式字段语法；
  - OpenAlex：`title.search:"<安全规范化目标>"`，`search_openalex` 识别后使用 `filter=title.search`；
  - 宽泛 `ranking_query` 独立保留；不追加第 4 条 query、不增加重试/探针。
- 安全规范化：NFKC、折叠空白、移除控制字符/引号/反斜杠/不安全标点、限制长度；不硬编码任何论文名、DOI、arXiv ID 或历史目录。
- 目标层级：
  - `title_direct`：名称在标题开头且后接副标题分隔符或结束；
  - `title_related`：标题含名称但带前缀、后缀或其他修饰，可能是扩展/变体/应用；
  - `abstract_mention`：仅摘要提及；
  - `unresolved`：无名称线索。
- `identity_status` 对简称保持 `unconfirmed_direct_title/title_related/abstract_mention`；只有用户提供的确切完整标题与来源标题一致时才标记 `confirmed_by_user_title`。`identity_basis` 记录判定依据。
- `metrics.source_query_audit` 记录每来源每条 planned/executed query、字段、模式、结果数量与失败代码；`target_coverage.targets[].query_execution`、`identity_status`、`identity_basis`、`coverage_reason` 供前端与 run.json 审计。
- 候选池仍保留完整 SBERT+RRF 排序，只保护 `title_direct` 线索进入 12 篇 Selector 池；`title_related` 不自动提升。最终 Top-k 仍由真实 LLM 选择，选择理由可说明原作未覆盖；未改原始 selected_papers、候补映射或失败尝试。

### 2.4 状态与阅读体验（角色 8/9）

文件：`src/paper_agent/services/pipeline.py`、`shared/contracts.ts` 及前端文件。

- 新增派生状态（不改原 `summary_scope`/`errors`）：
  - `missing`：进入分析但无总结产物；
  - `failed`：scope=failed 或没有可用验证内容；
  - `usable_partial`：有可用内容但范围/校验/论文级综合/覆盖不完整；
  - `complete`：fulltext（demo 为 demo_fixture）、无错误、overview/deep/research_question/core_idea/relevance 非空且有已验证证据。
- pipeline 新增 `summary_status_by_paper/counts`、`complete/usable_partial/failed/missing` ID 审计；target coverage 的 `summarized_paper_ids` 只计真实可用总结，`partial_summary_paper_ids` 不再包含 failed，并新增 failed/missing/complete/usable_partial 字段及 `coverage_reason`。
- `fulltext_summary_count`、`report_valid`、`completed/processing_complete` 的既有判定保持；`report_valid` 未改宽。报告可用输入改为所有有可用内容的非 failed 总结（不再要求必须已有 research_question），但部分报告仍被明确标记。
- 旧记录缺少新字段：前端 `summaryStatus` 按 scope/errors/真实内容推导；无法判断时显示 `unknown`，不默认成功；target 行对旧 `title_match` 显示“旧记录/身份未确认”，failed 不再计入“部分总结”。
- 报告 Markdown：新生成且无任何正文时只写简洁失败原因与保留引用，不输出整套空章节；旧报告 Markdown/JSON 不重写。前端 `reportHasSubstance` 检测旧空章节，无正文时显示失败原因、错误入口和真实产物操作，不再渲染空章节。可读但无效的部分报告继续显示，顶部持续标注 partial 与实际范围。
- 顶部收敛：目标覆盖改为默认折叠的 `<details>`，原始选择/候补审计默认折叠；报告顶部改为紧凑状态行 + 一行范围/总结状态；保留比较 Markdown、引用和旧 JSON 兼容。
- 专注阅读：`layoutStore.focusReading`（不持久化）隐藏侧栏/对话、让 Dock 占满窗口、正文最大宽度扩大；退出按钮（Dock 头部）或 Esc 恢复原三栏布局，标签、活动标签、会话和 Dock 状态保留；Dock 被关闭时自动退出专注模式。
