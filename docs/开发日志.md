# 开发日志

本文按版本保留项目的重要架构变化、实测结果和证据边界。当前版本为 **v0.2.2**；公共数据模型以[开发契约](开发契约.md)和[机器可读 schema](contracts.schema.json)为准。

## v0 基线：Python MCP 论文研究流水线（2026-10-23）

项目完成了十个开发角色的第一轮整合。Python 主 Agent 通过官方 MCP Python SDK 2.3.0 的真实 `Client` 连接 `MCPServer`；提供 Streamable HTTP 与 stdio 两种传输。服务端注册六个工具：搜索、Top-k 筛选、全文准备、单篇总结、综合报告和完整流水线。live 模式由模型返回工具调用；demo 使用明确标注的脚本控制器与合成数据。

当时的离线回归为 **282 passed、3 skipped**，Ruff 与 pip 依赖检查通过。MCP 客户端确实发现并调用了六个工具；Top-5 Demo 形成 18 个候选、5 份合成总结和报告，并保留 `partial_report`。这验证协议和模块组合，不验证真实论文相关性、模型质量或性能提升。

在线来源检查中，OpenAlex 返回 3 条记录；arXiv 连续遇到 HTTP 429，因此该次双源在线验收没有通过。另有三篇公开 arXiv PDF 完成下载和按页转换：两篇质量状态为 `partial_fulltext`，一篇通过文本覆盖启发式。文本页映射与保存的 Markdown 切片相符；启发式结果没有证明图表、公式或复杂版式完整。同期 5 次顺序与 5 次并发的结果属于 Demo smoke：真实模型请求为 0，加速比为 null。

## v0.2.0：Electron 桌面端与本地服务桥接

当前桌面目标是 Electron 主进程、preload IPC 和 React/TypeScript/Vite renderer。Python 主 Agent、MCP Client/Server、arXiv 与 OpenAlex 来源、PDF 处理、Selector Agent、Research Analyst 和持久化研究数据继续保留。界面只通过 preload 暴露的受限 API 访问 Python 服务；主 Agent 仍必须经 MCP Client 调用 MCP Server。

服务协议升至 API v3。Electron 主进程取得 loopback 服务 endpoint 与 bearer token，token 不进入 renderer 或诊断日志。服务信息、会话、任务事件、取消和受限 artifact 接口以[架构与接口](架构与接口.md)为准。沿用 `%LOCALAPPDATA%\Assignment\PaperAgent` 数据根和 `config.json`；没有 `conversation_id` 的旧 job 以只读历史显示，不改写旧记录。

本轮最终回归：Python **300 passed、3 skipped**，Ruff、TypeScript、生产构建通过；Electron 单测 **6/6**。源码生产模式、Vite HMR 模式和 Windows 解包发布程序的实际 Electron E2E 均通过，覆盖安全 preload、设置保存、Dock 分组/移动/重排/关闭/恢复/调整尺寸、真实 MCP 协议下的明确合成任务、运行中刷新恢复、事件重放、论文详情、报告导出/复制、性能 JSON 导入与合成标记、IME 输入、取消、窄窗口和关窗后服务存活。开发 HMR 后服务 PID 保持一致；测试没有提交真实模型或来源请求。

联调修复了 Windows 深目录中报告临时文件过长、未创建可选目录导致 artifact 读取 404、通知遮挡标签、IPC 漏传旧记录只读标记，以及终态事件与进行中轮询竞争导致漏读最终状态。开发模式使用随机 CSP nonce 允许 Vite 的 React refresh 引导代码；生产仍只允许本地脚本。

NSIS 安装版和 portable 已构建，解包程序包含冻结 Python 服务并通过生产 E2E。安装向导没有自动执行，macOS 未构建。离线 E2E 不证明 live 研究质量或真实并发性能。

原用户资料已在新发布程序中只读检查：7 个历史 job JSON 内容保持不变，两种 API Key 保持原值，旧记录只读提示正常；服务从空闲的 API v2 迁移到 v3，没有新增研究任务。

## v0.2.1：布局稳定性、真实流程与较大数据档位（2026-10-24）

本轮以现有 v0.2.0 为基线，不做架构重写。布局侧将 Sidebar 的“是否窄轨”收敛为 `compact || sidebarCollapsed` 单一状态源，折叠态的展开控制移入 58px 轨道可容纳的 footer；Dock 改为常驻挂载并在关闭时设置 0 宽度、`inert` 与 `visibility:hidden`，避免关闭面板丢失未保存设置、报告滚动位置和论文标签。拖拽手柄增加 pointer capture、pointercancel/blur/Escape 清理，修正 stacked 布局宽度计算和折叠态手柄误操作。

通信与任务侧透传后端 409/401 等错误正文，SSE 对 401/403/404/410 终止而不是无限重连，恢复轮询不再在约 19 秒后停止，任务快照按 `seq` 合并事件，显式检索词不再被 planner 改写，MCP 工具错误作为可恢复的 tool feedback 返回模型，分阶段主 Agent 路径补充 `total` 计时并去重错误。关闭窗口、刷新和 HMR 仍不会取消服务端任务。

离线回归：Python 304 passed、3 skipped；Ruff 通过；TypeScript typecheck、renderer/Electron 生产构建通过；Electron Node 测试 8/8；新增前端 layout store 测试 2/2；源码生产模式 Electron E2E 通过 12 项，新增 Sidebar 折叠/展开/快速切换/刷新持久化、Dock 关闭/重开保留未保存设置、1024px 侧栏折叠三项回归。v0.2.1 解包版使用本地 Electron 发行目录完成打包并通过同一套 12 项 E2E；由于 GitHub TLS 不可达，未下载 `winCodeSign`，关闭了 EXE 资源编辑/签名，安装包未重新生成。

## v0.2.2：菜单移除、中文化、Dock 标签栏与论文直读（2026-10-24）

本轮继续以现有 Electron + Python MCP 架构增量修复。原生应用菜单已移除，保留复制/粘贴/撤销/重做/全选、开发模式刷新与 DevTools 快捷键；renderer 默认 Dock 只保留论文标签，报告、活动、性能数据按需打开，避免新会话出现多个空占位。

运行时可读文本中文化：summary/report/selector 提示要求自由文本使用简体中文，但保留论文标题、paper_id、JSON 键、枚举和证据引文原文；错误文案与前端标签也改为中文，机器码保持不变。真实小规模运行（top_k=1，`data/validation/v021/stress/20261024T143559Z/`）生成中文单篇总结和 4,321 字符中文报告，报告引用真实论文 ID，整体为 partial；保留无 OA、部分页提取、候选超时和模型输出校验等真实错误。该轮 8 次物理模型请求、37,899 token、227.6 秒，未出现 `download_timeout`。

Dock 标签栏现在按面板实际宽度测量标签宽度；溢出时提供左右滚动按钮和“更多资料标签”菜单，完整标题可从菜单查看；标签槽不再把关闭按钮或焦点环裁掉，ResizeObserver 覆盖 Dock 缩放、分栏、窗口 Resize 和全屏。论文标签新增所属 job 身份；切换会话或重启后，PaperReader 会按 jobId 重新载入对应任务结果，替补论文也进入 `paperById`，不再误报“当前任务中找不到这篇论文”。

活动记录按阶段/工具聚合为可展开的 `details` 卡片，参数在展开后脱敏显示；composer 支持 72–190px 自增高、字数计数和运行时草稿，对话内增加最近阶段流。PDF 下载改为单候选 45 秒、单篇总预算 180 秒、连接超时 5 秒、最多 8 个候选，慢候选不会耗尽整篇预算。

离线回归：Python 307 passed、3 skipped；Ruff、TypeScript/build 通过；Electron 8/8；前端 8/8；源码 Electron E2E 16/16。v0.2.2 解包版 E2E 与打包结果见交付报告。
