## 3. 关键实现与契约

### 3.1 目标召回与受限候选池

- `plan_queries` 一次调用返回 `explicit_targets`、`queries`、`ranking_query`。目标必须能在用户原话中通过标准化 token 序列匹配；模型新增的论文名、别名、已知 ID 会被拒绝并记录审计。
- 来源查询仍最多 3 条；目标定向查询优先使用模型给出的真实查询，无法覆盖的 ASCII 目标用目标原文本身生成查询；非 ASCII 目标没有英文定向查询时保留目标并明确记录覆盖不足。
- `ranking_query` 独立用于现有 SBERT/RRF；缺失时回退到可用宽泛查询并记录 warning，不伪造。没有增加第 4 条查询或新的规划调用。
- 完整去重排序池保存在 `run.papers`。Selector 输入池由 `build_bounded_candidate_pool` 单独构造：
  - 至少覆盖请求的 Top-k（以实际候选数为限）；
  - `merged_candidate_limit` 不能把请求静默缩小到 k 以下，发生提升时记录 `merged_limit_raised_for_k`；
  - `candidate_limit` 不足时明确 `ValueError`，不悄悄请求更少；
  - 池外直接标题匹配候选可一对一替换池内末端非直接匹配候选，池大小不变并按完整排序稳定排序；
  - 审计 `base_pool_ids`、`selector_pool_ids`、替换对应、未进入池的直接匹配 ID。
- 标题匹配、摘要提及、未检索到分别记录。模型仍可在 Selector 中自行判断一个标题词面匹配究竟是原始工作、比较/后续还是无关论文；系统不把词面匹配宣称为已验证身份，也不硬改最终 Top-k。

### 3.2 有界全文候补

- 候补队列使用完整 `run.papers`，然后按“未覆盖目标的直接标题匹配 → 其他直接标题匹配 → 已有 OA PDF URL → 融合排名”稳定排序；OA 只影响全文尝试顺序，不进入学术相关性评分。
- 保持既有 `max_fulltext_attempts` 预算；该数值是原始 Top-k 之外的候补尝试次数，不是总论文数。下载候选数、单候选超时、单篇总预算、SSRF/DNS/私网/重定向/体积/原子写入均未扩大。
- 新增 `metrics.replacement_attempts`，每次候补记录：
  - 候补 ID、可确定的原始 ID 或 null、候补顺序；
  - 真实 `status`、`complete`、`readable`、失败码/失败码列表；
  - 是否进入最终分析、实际 summary scope（总结阶段后回填）、是否直接标题匹配、是否有 OA URL。
- 保留 `metrics.replacements` 只记录成功完整替补的语义；部分全文候补不会写入 `replacements`，而是在 `replacement_attempts` 和 `paper.metadata.fulltext_provenance` 中标记为 partial。分析论文可追溯到原始 Top-k 或候补尝试。

### 3.3 分块抽取与整篇综合

- `CHUNK_SYSTEM` 与 `MERGE_SYSTEM` 分开；内部 schema 也分开：
  - `_ChunkContent` 的全部字段必需，显式空字符串/空数组表示该块未报告；`{}` 或缺字段会触发 schema 修复/失败，不再自动补全成成功块。
  - `_ChunkEvidence` 不再有 `evidence_id` 字段；`source_segment_id`、quote、claim、类型等必需；未知/缺失 segment 会被拒绝。
  - `_MergeContent` 只允许 `{"evidence_id": ...}` 形式引用已验证证据，额外证据字段会触发 schema 校验；程序按 ID 还原完整记录。
- chunk 只使用当前 `source_segment_id` 内的连续原文，保留 NFKC/空白标准化、页码/章节/claim 校验；跨 segment 拼接、改写引用、虚构页码和 `evidence_id` 仍不会通过。引用真实不等于科学主张成立，提示词明确要求不过度声称。
- 每篇论文共享一次反馈修复（chunk 与 merge 共用），未提高请求/token/输出预算；非模型调用异常不再被误分类为 `invalid_model_output`，而是保留为调用失败。
- 仅把已验证、精简的分块笔记交给一次论文级 merge；merge payload 不再同时重复每块 evidence 全记录和 `verified_evidence`，而是 chunk 笔记引用证据 ID、证据目录只出现一次。最终 `PaperSummary.evidence` 仍保留全部已验证记录。
- 单 chunk 也执行论文级综合；merge 输入超预算或输出失败时保留结构化分块笔记并写 `llm_budget`/`invalid_model_output`/`llm_failed` 错误，不再拼接大量长文伪装深度笔记。merge 后深度笔记为空也会留下错误。
- `fulltext_summary_count` 现在要求 scope=fulltext、无 summary errors 且存在 overview/deep_analysis。

### 3.4 报告状态与可读性

- `generate_report` 的 partial 原因现在检查：
  - 可用总结不足 3 份；
  - 非 fulltext scope；
  - 实际 summary errors；
  - 缺少论文级 overview/deep_analysis（整篇综合未完成）；
  - 失败/不可用总结。
- 这些信息写入 `partial_report.details` 的安全字段（ID、scope、机器码、计数），引用仍可保留，但 live 的 `report_valid` 不会为 true；pipeline 额外要求所有总结 scope 正确、无 errors 且存在 overview/deep_analysis。
- 后端报告 Markdown 的 `论文比较` 段改为分节可读格式：`paper_ids` 保留为 `[paper_id]`，未知字段按键值逐项展示，不输出 `json.dumps` 原始行。
- 前端对旧记录做确定性兼容：只有能可靠识别的完整 JSON 值或逐行 JSON 对象块才格式化；合法数组对象展开；未知字段和引用保留；混合文本原样保留；无法解析的 JSON 段用安全代码块保留原文，不静默删除未知行。普通以 `[paper_id]` 开头的 Markdown 不会被误判为 JSON。

### 3.5 前端阅读体验

- 论文页新增紧凑“点名目标”区，按目标展示标题词面匹配、摘要提及、定向查询、Selector 池、最终分析、全文完整/部分、总结完整/部分、报告引用与报告有效性。
- 未到对应阶段时显示“等待筛选/等待全文/等待总结/等待报告”等中性状态；不以红色提前宣称终态。标题匹配明确标注为词面线索，不宣称已验证原始论文身份。
- 最终分析列表主编号固定为 1..N；关键词、语义、RRF、原始 LLM 名次仍在论文标签/排序依据中。原始 LLM Top-k 与全部候补尝试在折叠审计区，部分全文候补不显示为完整替补。
- 论文行分别展示“全文完整”“总结完整”“报告已引用”；报告页单独展示 `report_valid`。部分总结被引用不等于报告有效。
- 补齐 `conversion`、PDF 解析/编码、筛选调用失败、查询规划失败等中文标签；机器码保持稳定，未添加假恢复按钮。

## 7. 已知风险与限制

1. 真实 LLM 仍可能不遵守 chunk/merge JSON 契约，或产生 `quote_not_found`；本轮只修正了提示词/schema/证据目录边界，不放宽校验。每篇共享一次修复，因此多个坏块时仍可能保留 partial。
2. merge 输入仍可能超预算；此前会拼接长文，现在会保留结构化笔记并记录 `llm_budget`，但该论文不会得到完整深度笔记，报告也会真实降级。
3. 单 chunk 现在也会调用一次论文级 merge，模型请求总量仍受既有预算限制；预算耗尽时如实失败，不通过截断或拼接伪装成功。
4. 目标定向查询依赖模型返回英文目标查询；非 ASCII 目标若模型未给出英文定向查询，会保留目标并明确记录查询覆盖不足，不伪造已查询。
5. 标题直接匹配只是词面线索；UI 和 Selector 提示均不宣称已验证原始论文身份，最终是否选入和如何分析仍由 LLM 与真实下游结果决定。
6. 旧记录没有 `metrics.target_coverage` 时不显示目标覆盖，不凭空补造；旧报告比较段若无法可靠解析，会保留原文代码块，字段不会静默丢弃，但可读性可能不如新产物。
7. 前端只做静态修改，未实际启动 Electron 查看；CSS 断点、Dock 布局和长报告目录仍需协调者真实桌面验收。
8. 工作树中 `docs/本轮迭代验收_20261026.md` 的非本实现修改保持原样；未触碰 `config.py` 磁盘版本或任何用户配置。
