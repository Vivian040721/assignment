## 必须实现的用户可见结果

### 1. Sentence-BERT + RRF 真正接入

- 实现已有 `ranker=keyword|semantic` 配置分支。keyword 保持原有行为；semantic 使用 `sentence-transformers/all-MiniLM-L6-v2` 对英文 `ranking_query` 与论文标题、摘要编码，再融合原有关键词排名。
- 顺序必须是：双源检索 → 合并去重/关键词初排 → 全部去重候选的语义编码与 RRF → `merged_candidate_limit` 截断 → LLM Top-k。不得在截断后才做语义排序。
- RRF 固定使用 `0.5/(60+keyword_rank) + 0.5/(60+semantic_rank)`，排名从 1 开始；相同分数以原关键词排名稳定排序。本轮不调参、不声称权重最优。
- `initial_score` 保留原关键词分，`final_score` 保留 LLM 分。RRF 分和余弦相似度写入已有 `ranking_details`，不冒充概率或百分比。候选 `rank` 与 LLM 入选 `rank` 的语义先核查，再一致维护，独立保存 keyword/semantic/rrf ranks。
- 模型加载和编码放在线程中，进程级惰性复用、加载/推理锁、有界内容哈希向量缓存；不增加向量数据库、其他来源或复杂编排。
- 可选依赖已在 `pyproject.toml` 声明，优先复用；在 `.venv-v2` 安装并准备实际模型缓存。不得只写依赖声明后称为已接入。保留原有 keyword 默认/用户设置；验收时由协调者使用进程级 `PAPER_AGENT_RANKER=semantic`，不覆盖用户配置。
- 运行 `metrics` 记录 requested/actual ranker、模型、候选数、耗时、降级子原因；论文 `ranking_details` 保留 keyword_rank、semantic_rank、cosine_similarity、rrf_rank、rrf_score、模型标识。前端能读取已有后端信息，必要时只补齐现有字段的 TypeScript 可选类型。
- 依赖缺失、模型加载/下载/编码失败时完整回退原关键词顺序，记录安全的机器子原因与中文提示。不得保留半套语义更新，不能以 semantic 标签掩盖降级。
