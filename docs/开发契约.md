# 开发契约 v2

本项目继续使用 `paper_agent` 包和单一仓库。测试统一放 `tests/`，文档放 `docs/`，运行产物放被 Git 忽略的 `data/`。公共模型在 `models.py`；旧 `schemas.py` 已移除，旧记录只通过只读兼容层展示。模型禁止未知字段，文件路径保存字符串，所有可变字段使用独立默认值。

## 公共模型

| 类型 | 必需字段 | 主要扩展字段 |
| --- | --- | --- |
| Paper | paper_id, title | authors/year/abstract/doi/arxiv_id/arxiv_version/sources/source_records/paper_url/pdf_url/pdf_urls/citation_count/initial_score/final_score/rank/selection_reason/ranking_reason/ranking_details/pdf_path/markdown_path/page_map/fulltext_quality/status/error/errors/metadata |
| PaperSummary | paper_id | title/summary_scope/research_question/core_idea/methods/experiments/findings/limitations/relevance/evidence/author_claims/system_inferences/speculative_ideas/warnings/summary_path/markdown/errors |
| ResearchReport | idea | overview/related_work/comparison/researched_questions/limitations/research_directions/references/report_path/markdown/errors |
| PipelineResult | idea | run_id/query/queries/mode/execution_mode/top_k/papers/selected_papers/summaries/report/source_counts/timings/tool_calls/errors/metrics/status/output_dir |
| ErrorInfo | code, message, stage | paper_id/retryable/details |
| StageTiming | stage, duration_seconds | request_count/success_count/error_count |
| ToolCallRecord | tool | arguments/duration_seconds/status/controller/error |
| PageMapping | page_number | text/start_char/end_char |
| EvidenceReference | paper_id | page_number/section/quote/claim/evidence_type |
| PaperReference | paper_id, title | paper_url/doi |

`initial_score`、`final_score` 均为 0 到 1，`rank`、`page_number` 从 1 开始。`arxiv_id` 为不含版本的基础 ID，`arxiv_version` 保存 `v2` 等字符串；来源原始记录放 `source_records`。`paper_id` 必须稳定，去重后保留来源。`page_map` 保存 Markdown 中的字符起止位置，页面质量、页数和部分解析信息放 `fulltext_quality`。

`summary_scope` 限定为 `fulltext`、`partial_fulltext`、`abstract_only`、`failed`、`demo_fixture`，默认 `abstract_only`，不能在缺失全文时升级范围。`methods/experiments/findings/limitations/author_claims/system_inferences/speculative_ideas/warnings` 是字符串列表。证据类型为 `author_claim`、`system_inference` 或 `research_idea`。`comparison` 为结构化字典列表，其引用 ID 必须来自实际总结。

`Paper.status` 使用可扩展字符串，约定主状态：`metadata_only` → `selected` → `downloaded` → `converted`，失败使用 `no_open_access`、`download_failed`、`conversion_failed`、`partial_fulltext`、`failed`。`error` 提供简短人类可读原因，`errors` 保留可机器处理的信息。流水线状态建议 `pending/searching/selected/fulltexts_ready/completed/partial/failed/demo_completed`。完整成功的判定由流水线核实全文质量、总结范围和报告；不能只检查状态文字。

流水线保留 `selected_papers` 中的原始相关性 Top-k。全文候补替换记录在 `Paper.metadata` 或 `PipelineResult.metrics`，不能改写原始选择来源。`papers` 保存合并后的候选。`metrics` 可放计数、候补映射和 LLM 请求统计。`ToolCallRecord` 由主 Agent 在每次真实 MCP 工具调用后写入 `PipelineResult.tool_calls` 与 `trace.jsonl`，`controller` 区分 `model_tool_call` 与 `scripted_demo`。

## 统一模块函数

```python
async def search_arxiv(query: str, limit: int, *, settings=None, client=None) -> list[Paper]: ...
async def search_openalex(query: str, limit: int, *, settings=None, client=None) -> list[Paper]: ...
def merge_dedupe_rank(papers: list[Paper], idea: str) -> list[Paper]: ...
async def select_top_k(idea: str, papers: list[Paper], k: int, *, settings=None, llm=None) -> list[Paper]: ...
async def download_pdf(paper: Paper, *, settings=None, client=None) -> Paper: ...
async def convert_pdf(paper: Paper, *, settings=None) -> Paper: ...
async def summarize_paper(idea: str, paper: Paper, *, settings=None, llm=None) -> PaperSummary: ...
async def generate_report(idea: str, summaries: list[PaperSummary], *, settings=None, llm=None) -> ResearchReport: ...
```

`settings` 类型为 `Settings | None`，`client` 为可注入的 `httpx.AsyncClient | None`，`llm` 为 `LLMClientProtocol | None`。可提供持有同样依赖的类，模块函数仍保留为入口。HTTP 客户端由创建者关闭，模块不得关闭外部注入的客户端。异步函数不得阻塞事件循环；PDF 转换需线程/进程执行池。

来源失败应抛携带 `ErrorInfo` 的来源异常，由流水线收集；空列表只代表成功检索但没有结果。单篇下载和转换失败返回带状态与错误的 Paper，让其他论文继续。LLM 筛选不能悄悄退回规则排序冒充 Agent；如启用 `selector_fallback='initial_ranking'`，必须显式标记降级和原因。

## 配置与 LLM 注入

`Settings` 保留 frozen dataclass 与所有旧字段；`processing='serial'|'concurrent'` 是构造配置字段，`execution_mode` 为只读映射属性 `sequential|concurrent`。`PipelineResult.execution_mode` 使用后者。默认 Top-k 为 5、每源 20、候选 15。默认 `output_dir=data/runs`；`data_dir=data` 派生 pdfs、markdown、summaries、reports 路径，四个目录也可分别覆盖。配置不会主动创建目录。

v0.2.2 将 PDF 下载默认预算调整为单候选 45 秒、单篇总计 180 秒、连接超时 5 秒、最多 8 个候选；新增 `download_candidate_timeout` 环境变量。v0.2.1 增加四个可选规模控制字段：`merged_candidate_limit=0`（0 表示保留全部去重候选，非 0 时在排序后截取该数量进入后续阶段）、`selector_input_token_budget=0`（0 表示回退到 `llm_input_token_budget`）、`report_input_token_budget=64000`（0 表示回退到 `llm_input_token_budget`；报告提示只发送每篇前 3 条证据，完整证据保留在单篇 summary artifact 中）、`max_fulltext_attempts=0`（0 表示不限制候补下载次数）。对应环境变量为 `PAPER_AGENT_MERGED_CANDIDATE_LIMIT`、`PAPER_AGENT_SELECTOR_INPUT_TOKEN_BUDGET`、`PAPER_AGENT_REPORT_INPUT_TOKEN_BUDGET`、`PAPER_AGENT_MAX_FULLTEXT_ATTEMPTS`。`scripts/stress_run.py` 可用 40/40/30/8 档位运行，不改变日常检索与候选默认值。

注意：`dataclasses.replace(existing, data_dir=...)` 会保留已派生的四个路径。隔离实验时需同时显式设置 `pdf_dir`、`markdown_dir`、`summaries_dir`、`reports_dir`，或将其重置为 `None` 后重新派生。当前 benchmark 已分别指定四个目录。

独立并发配置为 `search_concurrency`、`download_concurrency`、`conversion_concurrency`、`llm_concurrency`。缓存配置 `cache_enabled` 与 `cache_mode=off|read_only|read_write`，基准实验必须一致。下载限制使用 `max_pdf_bytes/max_redirects/download_timeout`。来源请求采用 `http_max_retries/http_retry_backoff/http_timeout`，arXiv 请求间隔不少于 `arxiv_request_interval=3` 秒。

`llm_client.ChatClient` 与旧 `llm.ChatClient` 指向相同实现：

```python
client = ChatClient(settings, client=injected_httpx_client)
message = await client.chat(messages, tools=tools)  # 原样保留真实 tool_calls
text = await client.text(system, user)
data = await client.json(system, user)  # response_format=json_object + 本地校验
typed = await client.structured(system, user, ResponseModel)  # Pydantic 校验
counts = client.usage.to_dict()
```

`LLMClientProtocol` 仅要求 `chat/text/json`，因此测试可注入无密钥 Fake LLM。真实 `ChatClient` 要求有效地址、模型名和密钥；mock HTTP 测试用明确假的凭据。共享一个 ChatClient 才能共享并发配额和预算。密钥在 Settings repr 中隐藏，不进入调用日志、异常或源码。

超时使用 `llm_timeout`。只重试连接/超时、408、429 与 5xx；每逻辑调用最多 `1+llm_max_retries` 次 HTTP 请求。退避有上限且解析数字形式的 Retry-After。鉴权、响应结构和 JSON 错误直接失败。结构化错误通过 `LLMOutputError` 报告，预算错误通过 `LLMBudgetError`，均继承 `LLMError(RuntimeError)`。不包含服务端响应正文，以免泄露信息。

`usage.requests` 是实际 HTTP 尝试数，含失败重试；`logical_calls` 为 chat 入口调用数（含预算拒绝），`retries` 为重试调度次数。`successful_requests` 表示 Chat 响应结构有效，不代表后续 JSON 语义通过；`invalid_outputs` 单独记录 JSON/结构化校验失败。Token 数来自服务提供方 usage；缺失 usage 单独计数。`llm_max_calls` 是 HTTP 请求预算，`llm_max_total_tokens` 是已观察 Token 的停止阈值，并非精确账单保证（输入及并发请求的未知用量不能预先得知）。`llm_max_output_tokens` 限制输出，`llm_input_token_budget` 供 selector/research 估计输入预算。无真实密钥时只报告 mock 验证，不宣称真实 LLM 已运行。

## 旧模型迁移

协调层负责适配：`PaperRecord.landing_url→Paper.paper_url`、`oa_pdf_url→pdf_url`、`base_score→initial_score`（旧得分需先归一化），其余同名字段映射。`RunResult.input_idea→PipelineResult.idea`、`processing.serial→execution_mode.sequential`。旧字典 timings 转成 StageTiming；旧字符串 errors 转成 ErrorInfo。旧 SelectedPaper 必须与真实候选联结后生成 Paper，不能丢失 DOI/来源。旧示例只能标记 demo_fixture。不得将旧 RunResult 和新 PipelineResult 当成可互换对象直接传递。
