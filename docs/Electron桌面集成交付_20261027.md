## 3. Electron 运行时核查结论（只读）

按分工对主进程/preload/IPC/安全做了逐项只读核查，未发现需要修改的缺陷：

- 安全边界齐备且与 AGENTS.md 一致：`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、`webSecurity: true`、`webviewTag: false`、`setWindowOpenHandler` 拒绝、`will-navigate/will-redirect/will-frame-navigate/will-attach-webview` 全部 preventDefault、权限请求与检查一律 `false`。
- IPC 全部经 `assertTrusted` 校验发送者（主窗口、主框架、file: 指向内置 renderer 或 dev origin 5173）；`registerHandler` 统一错误脱敏（`safeError`）。
- token 只存在于主进程 `ServiceClient`；`ServiceInfo`/`PublicConfig` 校验器不返回密钥；E2E 运行时断言 `'token' in info === false`、`api_key` 不在 `PublicConfig` 中、secret 输入框为空。
- artifact 打开/导出经 `safeFilename` 限制扩展名与 kind、绝对路径；外部链接仅 HTTP(S) 且拒绝内嵌凭据。
- SSE 订阅有界（单发送者 ≤32、序号去重、45s 看门狗、指数退避重连、401/403/404/410 语义区分）；窗口导航/销毁/渲染进程消失时清理订阅。
- 服务单实例由 `service_control` 锁文件保证（同 data root 重复启动返回既有 endpoint），不会产生多个失控 daemon；关窗不停止服务（E2E `daemon-survives-window-close` 实证）。

## 4. E2E 新增覆盖（iteration-2 桌面可见契约）

在真实 Electron + 真实 Python 服务（demo 夹具，零 live 调用）的链路中新增一项检查 `report-validity-scope-readable-comparison-stable-numbering`：

- 报告状态、任务状态、报告有效性三个 chip 必须分别展示且互不混淆：demo 任务只有 1 篇总结（少于 3 篇）→ 状态「部分结果报告」，但 `report_valid=true` → 「报告有效」，任务状态「演示完成」。这正对第二轮任务单「部分总结被引用不等于报告有效」「分别展示」的要求。
- 报告范围计数展示总结 scope（「演示样例」），不与「全文完整」混同。
- 报告比较段在**存储 artifact 原文**与**前端渲染结果**两处都必须为可读 Markdown（`## 论文比较`、`### 比较 1：[demo:001]`、`synthetic fixtures only`），且不得泄露 `"paper_ids"` 原始 JSON——锁定 iteration-2「比较从 JSON 行改为可读 Markdown」的后端契约与前端渲染兼容。
- 最终分析列表主编号为稳定 1..N（`.paper-rank` = 1），论文行标签区分「演示样例」scope、「全文完整」、「报告已引用」。
- 源码模式启动优先复用 `node_modules/electron/dist` 中与 devDependency 固定的二进制（`PAPER_AGENT_ELECTRON_EXE` 可覆盖），规避受限网络下 Playwright 从 CDN 下载 Electron 超时导致 E2E 无法启动的问题；不影响原有打包模式参数。

## 5. Electron 单测新增（IPC 边界）

`tests/electron/security.test.mjs` 由 8 例增至 12 例，全部实跑通过：

- `validateJob`：标识格式、idea 长度、events 数组上界（100000）、artifacts 标识与文件名边界。
- `validateArtifactText` / `validateArtifactLocation`：内容 2 MiB 上界、`truncated` 布尔类型、绝对路径要求、路径长度上界。
- `validatePublicConfig` / `validateServiceInfo`：缺字段、错类型、`default_execution_mode` 枚举、pid/active_jobs 非法值拒绝。
- `validateConversation`：messages 非数组、单条 content 2,000,000 字符上界、message.job_id 标识格式。

## 8. 已知风险与限制

1. `onnxruntime` ≥1.21 在本机不可用（access violation）；本机 venv 使用 1.20.1 完成验证。lock 文件未改，需角色 1 决策是否增加 CPU 兼容上限。若在其他机器按 lock 重建环境，行为以该机为准。
2. E2E 对 demo 夹具的结构断言（chip 文案、编号、比较段格式）与 iteration-2 后端/前端契约绑定；后续契约变更需同步更新本文件断言。
3. E2E 源码模式复用本地 Electron 二进制；若 `node_modules/electron` 缺失且网络不可达，E2E 仍会因无法下载 Electron 而失败（此时应提示而非静默）。
4. 本轮未运行 live 研究、未调用真实模型；桌面结论不构成论文质量或性能证据。
5. Windows 长路径/磁盘空间未在本轮复测；打包产物位于 gitignore 的 `data/release/`，不会入库。
